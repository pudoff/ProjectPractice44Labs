
# Технический отчёт

**Проект:** ProjectPractice44Labs
**Рабочий комплект:** ProjectPractice44Labs-offline-kit
**Дата проведения работ:** 31 октября 2026 г.
**Испытательная платформа:** macOS, Apple Silicon (ARM64)

## 1. Общие сведения

В рамках работы выполнены подготовка программного окружения, контейнеризация компонентов и проверка автономной работы системы преобразования растровых изображений инженерных чертежей в формат DXF.

Система предназначена для автоматизированной обработки изображений технических чертежей. В процессе обработки выполняются анализ изображения, распознавание текстовых элементов, выделение геометрических примитивов и формирование векторного файла DXF.

В качестве основы использован существующий программный конвейер обработки изображений Pipeline B. Для организации работы с заданиями применяются HTTP API, отдельный обработчик задач и база данных PostgreSQL.

Работа охватывает следующие требования:

- **1.1. Подготовка воспроизводимого программного окружения:** настройка Python и Poetry, фиксация зависимостей, подготовка API и worker, организация локального хранения OCR-моделей.
- **1.2. Контейнеризация приложения:** развёртывание API, worker и PostgreSQL с помощью Docker Compose, настройка общих каталогов и постоянного хранилища.
- **1.3. Автономное развёртывание и проверка:** подготовка локальных Docker-образов и OCR-моделей, контроль целостности файлов, испытания без подключения к интернету и сохранение диагностических журналов.

## 2. Цель и задачи работы

**Цель работы** — обеспечить воспроизводимый запуск системы преобразования PNG в DXF и подтвердить возможность обработки изображения на подготовленном компьютере без доступа к интернету.

Для достижения цели выполнены следующие задачи:

5. Организованы каталоги для входных изображений, результатов и OCR-моделей.
6. Подготовлены Docker-образы и архив моделей для автономного использования.
7. Устранены обнаруженные ошибки конфигурации.

10. Выполнена программная проверка структуры DXF.

## 4. Выполнение требования 1.1. Подготовка воспроизводимого окружения

### 4.1. Управление зависимостями

Для управления зависимостями применяется Poetry.

Конфигурация проекта содержится в `pyproject.toml`. Файл `poetry.lock` фиксирует разрешённые версии используемых пакетов.

При первоначальной настройке обнаружено, что сценарии запуска требовали Poetry 2.2.1, тогда как на испытательном компьютере была установлена версия 2.5.1.

Проверки версии были скорректированы. После этого Poetry успешно создал виртуальное окружение с Python 3.12.8.

### 4.2. Подготовка API и worker

Для организации обработки изображений используются два программных компонента:

- **API** — принимает изображение, создаёт задание, предоставляет сведения о его состоянии и позволяет скачать результат.
- **Worker** — получает задания из базы данных, запускает обработку изображения, выполняет распознавание и векторизацию, сохраняет DXF и обновляет состояние задания.

Для хранения сведений о заданиях используется PostgreSQL.

Дополнительный брокер сообщений в проверяемой конфигурации не применяется.

### 4.3. Подготовка OCR-моделей

Для распознавания текста используется RapidOCR с локальными ONNX-моделями.

Модели размещены в каталоге `models/`, который подключается к контейнеру worker по пути `/models`.

При первоначальной проверке обнаружена ошибка инициализации классификатора текста. RapidOCR пытался записать модель:

`ch_ppocr_mobile_v2.0_cls_mobile.onnx`

в каталог `/models`, доступный только для чтения.

Для устранения ошибки модель была загружена в локальный каталог `models/`.

После этого повторное задание на обработку изображения завершилось успешно.

Дополнительная модель включена в обновлённый автономный архив. Контрольные суммы архивов сформированы повторно.

Автономный запуск выполняется сценарием:

```bash
bash scripts/start_offline.sh
```

### 6.2. Корректировка сценария автономного запуска

При первом автономном запуске возникла ошибка проверки контрольных сумм.

Проверка выполнялась после перехода в каталог `offline/`, тогда как пути в `SHA256SUMS` уже содержали префикс `offline/`.

В результате программа искала файлы по неверному пути.

Сценарий был исправлен для выполнения проверки относительно корня проекта:

```bash
sha256sum -c offline/SHA256SUMS
```

Дополнительно архив OCR-моделей обновлён после добавления модели классификатора текста.

### 6.3. Проверка целостности автономных архивов

Для проверки использована команда:

```bash
sha256sum -c offline/SHA256SUMS
```

Получен результат:

```text
offline/docker-images.tar: OK
offline/ocr-models.tar.gz: OK
```

Обе контрольные суммы совпали.

Это подтверждает соответствие проверенных архивов значениям, зафиксированным в `SHA256SUMS`.
