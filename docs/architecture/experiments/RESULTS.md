# Эксперименты ревью: насколько обобщается автоматический конвейер (вариант B)

Дата: 25.10.2026. Конвейер: `runs/klapan_png2dxf/pipeline_b/`. Сравнение: `tools/compare_dxf.py --align geom`
(слой `DEFPOINTS` исключён; размеры дополнительно сравниваются по значению; текст — по центру строки).
Эталон тестового листа `клапан.dxf` читается только скриптом сравнения.

Воспроизведение:
```bash
export PYTHONUTF8=1; P=.venv/Scripts/python; E=docs/architecture/experiments
$P $E/run_b_batch.py --batch_b_v5 && $P $E/recompare.py batch_b_v5   # 9 листов
$P $E/robustness.py robustness_v4                                    # «скан» и синтетика
```

## 1. Что меняли (найдено ревью, исправлено в `pipeline_b`)

| # | ошибка | где | симптом | исправление |
|---|---|---|---|---|
| 1 | Край листа = крайние длинные линии | `raster.calibrate` | на 5 из 9 листов нет линии обреза → внутренняя рамка 395×287 принята за 420×297, масштаб −6 %, px/мм по x и y разные (22,13 / 22,75) | две гипотезы (обрез / рамка с полями ГОСТ 2.301 20/5/5/5), выбор по согласию масштабов x и y |
| 2 | Положение линии по краю штриха | `raster.calibrate` | у толстой рамки (≈0,7 мм) сдвиг ≈0,35 мм → F1@0,25 0,55–0,59 при F1@1 0,90–0,98 | центр серии строк/столбцов |
| 3 | Маска стирания «точек» расширялась целиком для каждой точки | `symbols.detect` | на скане 365 пятен → стёрто 86 % чернил | расширяется только контур найденной точки |
| 4 | Порог морфологии стрелок в мм от 600-dpi рендера | `symbols.detect` | размытые линии скана (0,49 мм) проходят как «залитые» → ложные стрелки; первая попытка (медиана толщины) **сломала** 3 чистых листа (размеры 20 → 3) | порог = max(0,42 мм; 1,6 × толщина *тонкой* линии, 20-й процентиль) |
| 5 | Шаг штриховки по всем 45°-линиям листа | `hatch.find_families` | виды перемешиваются, гистограмма решает 14:13 → сдвиг 0,06 мм убирал всю штриховку клапана | шаг по ближайшему перекрывающемуся соседу (локально) |
| 6 | Фаза штриховки — медиана остатков по модулю | `hatch.find_families` | разрыв на границе 0/шаг | круговое среднее |
| 7 | Метрика: рамка на `DEFPOINTS`, `∅`/`Ø`, М/Х кириллицей | `tools/compare_dxf.py` | выравнивание сдвигалось на 20 мм; верные размеры считались пропущенными | слой исключён; нормализация + recall по значению |

Попытка, давшая ухудшение и откатанная: масштаб OCR по px/мм (на скане 200 dpi CER 0,51 → 0,57).

## 3. Устойчивость к сканированию

Клапан, искажённый как архивный скан: 200 dpi, поворот 0,8°, размытие, шум, неровный фон, пятна, JPEG q=55.
`cut` — дополнительно обрезан внутри линии обреза (край бумаги). Синтетика — `dataset/data/pdf/drawing_00{1,2,3}.pdf`
при 200 dpi против их DXF.

| случай | F1@0,5 до | F1@0,5 после | F1@1 после | примитивы R / P | размеры по значению до → после | текст точных / CER |
|---|---|---|---|---|---|---|
| скан 200 dpi с краем листа | 0,401 | **0,792** | 0,827 | 0,524 / 0,636 | 0,286 → 0,214 | 0,203 / 0,508 |
| скан 200 dpi, обрез по краю | 0,085 | 0,190 | 0,315 | 0,073 / 0,137 | 0,071 → 0,179 | 0,145 / 0,714 |
| синтетика 001 | 0,553 | 0,648 | 0,955 | 0,533 / 0,629 | 0 → 0 | 0,000 / 0,950 |
| синтетика 002 | 0,156 | 0,171 | 0,376 | 0,000 / 0,082 | 0 → 0 | 0,000 / 0,963 |
| синтетика 003 | 0,153 | 0,172 | 0,368 | 0,064 / 0,125 | 0 → 0 | 0,032 / 0,927 |

Выводы:
- Исправления 3–4 вдвое подняли геометрию на скане (0,40 → 0,79), но **размеры и текст на скане остаются плохими**
  (≈0,2 и CER 0,5): правила для стрелок и предобученный OCR не рассчитаны на размытые 200 dpi — это место для обучаемых
  детектора и распознавателя, а не для подбора порогов.
- **Скан, обрезанный по краю бумаги, не калибруется**: крайние длинные линии — доп. графы слева (x = 8/13 мм), рамка не
  находится → нужен этап регистрации листа по шаблону ГОСТ (рамка + штамп 185×55 + доп. графы).
- Синтетика: нет рамки → калибровка по размеру изображения; в эталонах длинные диагонали (все 150 файлов) и нулевые
  отрезки, размеры «взорваны» → низкие числа отражают и качество набора, и отсутствие опоры для выравнивания.
  Для оценки сканов нужна регистрация по подобию (RANSAC/ICP), а не по габариту.
