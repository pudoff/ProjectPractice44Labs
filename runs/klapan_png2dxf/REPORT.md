# Оцифровка чертежа «Клапан предохранительный»: PNG → DXF

Проект выполнен совместно с **44labs** (MVP оцифровки архивной конструкторской документации).
Исходник: `runs/клапан.png` (9925×7017 px, А3, 1:1). Дата прогона: 24.10.2026.

## 4. Вариант A — как сделано

`build_variant_a.py` строит лист кодом. Растр использовался только для привязки видов (одна точка на вид) и расположения надписей/знаков.

- **Главный вид от размеров.** Якоря: ось y = 160,41, торец x0 = 54,30. Дальше всё из чисел: торец ⌀42 = x0+10, правый торец = x0+46, ступень = −5,5, левый торец обода = −4, торец ступицы = −14, конец резьбы = −20, дно сверления = −25, фаска 1,6×45°; ⌀28/32/42/22/135/150/160. Конус 60° с толщиной стенки 4, наружная образующая проходит через кромку ⌀42 (подтверждено растром до 0,006 мм). Скругления — касательные (решение уравнений касания), профиль строится для верхней половины и зеркалится; один замкнутый контур идёт и в линии, и в границу HATCH.
- **Неуказанные радиусы** (ТТ п.2 «3…5 мм») и мелкие переходы подобраны по минимуму среднего расстояния до скелета штриха: буртик→канавка R3, конус→обод R3,5, конус→⌀135 R3; R2, R3, R7 — как подписано. Сверление под резьбу нарисовано ⌀9,8 (как на листе; это изображение внутреннего диаметра M12×1,5).
- **Вид А(5:1)** — та же геометрия ×5 от одной точки; волнистая линия обрыва — SPLINE по точкам, снятым с сетки 1 мм. **«Вариант»** — та же ступица (смещение (132,5; −30,41)) с ⌀32 и фаской 1,5×45°. **Вид В** — прямоугольник 30×15 строго по размерам, контур — замкнутый SPLINE.
- **Размеры: 28 настоящих DIMENSION** (линейные, диаметральные с `%%c`, радиальные, угловой 60°, толщина 4⁺¹ по нормали к стенке, половинный ⌀22 с одной стрелкой, в виде 5:1 — `DIMLFAC=0,2` + явный текст). Тексты: `%%c150%%p0,5`, `M12x1,5-H7`, `<>x45%%d`, `<>{\H0.7x;\S+1^ ;}`. Положения размерных линий и текста — как на листе; стиль ESKD: текст 5, стрелки 3×1, выступ 2, зазор 1, десятичная запятая.
- **Штриховка** ANSI31, шаг 2,5 мм, фаза линий подобрана так, что они ложатся на линии растра. Осевая — собственный CENTER 6/1,5/1/1,5 (как на листе).
- **Аннотации:** знаки шероховатости — блок `ESKD_ROUGH` (вставка с поворотом) + текст, база Б (рамка + залитый треугольник), рамка биения, выноски — LEADER, буквы видов, знак «повёрнуто», общий знак «√○(√)».
- **Текст:** шрифт `isocpeur.ttf` с наклоном 15° (есть в стандартном AutoCAD, содержит кириллицу), ТТ — 12 строк TEXT h=5 с шагом 8,53 мм, штамп и доп. графы полностью.
- **Итерации:** рендер DXF → наложение на растр (`work/overlay.py`, чёрный — совпало, серый — только растр, красный — только DXF) → правка. Устранено: зеркалирование профиля, выравнивание TEXT (BOTTOM ≠ базовая линия), высота размерных чисел в LibreCAD, `$DWGCODEPAGE`, верхний индекс «⁺¹», геометрия радиальных размеров (см. §9). Итоговые наложения: `compare/raster_overlay_A.png`, `compare/raster_diff_A.png`.

## 5. Вариант B — как сделано

`pipeline_b/` (CLI: `pipeline.py IN.png OUT.dxf`, описание — `pipeline_b/README.md`). Ничего, специфичного для этого листа: только правила ЕСКД.

1. Бинаризация Otsu, оценка/исправление перекоса, калибровка по линии обреза; формат — из OCR «Формат А3».
2. OCR: RapidOCR (ONNX, PP‑OCRv6 det + PP‑OCRv5 **eslav** rec — кириллица) в два прохода (0° и 90° для вертикальных чисел) + целевой дозапуск OCR у «осиротевших» стрелок на дугах.
3. Символы: стрелки (морфологическое открытие + PCA, остриё — по «коридору» до выносной), залитые треугольники баз, точки.
4. Удаление глифов, попавших в рамки OCR, и стрелок → скелетизация → отрезки/дуги → слияние коллинеарных, привязка углов.
5. Осевые/штриховые: цепочки коллинеарных штрихов с проверкой, что разрывы пустые (иначе это сплошная линия, разрезанная штриховкой).
6. Штриховка: семейства параллельных равноотстоящих отрезков → HATCH (шаг/фаза измерены), граница — заливкой по контурным линиям.
7. Размеры: пары соосных встречных стрелок → DIMENSION; выносные — вдоль перпендикуляра до Т‑узла; текст — ближайшая OCR‑строка, **значение которой совпадает с измерением** (или отношение = масштаб вида 2/2,5/4/5/10 → `DIMLFAC`); ⌀ — по симметрии относительно найденной оси; R — стрелка на дуге + надпись «R…»; угол; прочие стрелки → LEADER.
8. **Подгонка геометрии под размерные числа:** МНК по кластерам координат x/y (9+9 ограничений, сдвиги ≤ 0,034 мм).
9. Знаки шероховатости (пары штрихов 60°, 1:2) → слой DIMS; поля штампа → TEXT и пользовательские свойства DXF (наименование, материал, масса, масштаб, формат — для поиска в архиве).

Время (`out/klapan_variant_B.run.json`): загрузка 3,0 с, OCR 3,5 с, символы 0,2 с, векторизация 3,4 с, штриховка 0,3 с, размеры 1,4 с, чистка 1,4 с, запись 0,1 с — **≈ 13,5 с на лист** на CPU (ориентир заказчика 5–10 мин выполнен с большим запасом).

## 8. Расхождения и причины

**Вариант A**
- `М12х1,5-Н7` (эталон, кириллица) ↔ `M12x1,5-H7` (у меня латиница, как читается на листе) и `4` (эталон) ↔ `4⁺¹` (у меня допуск записан в размер) — по смыслу совпадают, метрика считает разными строками.
- Буквы видов «А», «М» у меня кириллические, в эталоне латинские; в эталоне «Листов» и «1», «4» и «+1» — отдельные TEXT, у меня одной строкой.
- Классы слоёв 0,795: знаки шероховатости, рамки базы/допуска, полки выносок у меня на DIMS (требование «размерная графика — DIMS»), в эталоне — тонкие линии; линии штампа у меня частично MAIN, в эталоне THIN.
- Канавка обода: подписано R2, нарисовано r 1,5 (глубина 1,5 согласуется только с r 1,5) — оставлена геометрия листа и текст «R2». Это несоответствие в самом оригинале.
- Неуказанные литейные радиусы (3…5) подобраны по растру: 3 и 3,5 мм; ⌀ сверления 9,8 — как изображено.
- Шрифт: isocpeur вместо исходного ГОСТ‑шрифта (подменяемость в AutoCAD важнее точного начертания) — ширина надписей отличается от растра на 5–15 %.
- Положение текста R7 и других радиусов/полок в некоторых местах отличается на 0,5–4 мм от листа — ограничение раскладки размеров ezdxf (см. §9).
- Не воспроизведены разрывы линий контура/выносных под текстом и размерными линиями (артефакт оригинального оформления).

**Вариант B**
- Не собраны размеры: R7 (OCR не прочитал надпись у полки), ⌀22 (половинный размер с одной стрелкой), ⌀ у «32» в «варианте» (ось вида не распознана), текст «1,5×45°» в «варианте» не привязался (показывает измеренное 1,5).
- Штриховка найдена не полностью (5 HATCH, суммарно 1189 мм² против 2757 в эталоне): часть отрезков штриховки не попала в семейство из‑за обрывов при удалении текста/стрелок, они остались отдельными линиями.
- OCR: «Б»→«D», «0,2 Б»→«0,26», «⌀» читается как 0/6/$ (исправляется по геометрии), «Рук. гр.»→«Pyk 2p.», «Утв.»→«ym8.», «ГОСТ»→«ГОст», «IIА»→«11А», «±IT15»→«±1T15»; обозначения видов «А», «В», «М» не прочитаны и остались векторными штрихами.
- Классы слоёв 0,56: одинаковая толщина штрихов на рендере не позволяет отделить тонкие линии от основных — используются эвристики (длина, участие в размерах/штриховке).
- Дополнительные короткие отрезки — остатки глифов и пересечений; дуги иногда разбиты на несколько.

## 9. Что выяснилось про инструменты

- ezdxf перезаписывает `$DWGCODEPAGE` из `doc.encoding` → в `eskd_dxf.new_drawing()` добавлено `doc.encoding = "cp1251"`, в `verify()` — проверка.
- LibreCAD пересчитывает размеры по заголовочным `$DIM*`, а не по стилю → `new_drawing()` дублирует параметры стиля ESKD в заголовок.
- `add_radius_dim(location=…)` выводит точку на дуге из `location`; для полок «через центр» нужно задавать `defpoint4` явно — тогда `location` = конец полки. Верхний индекс — `\S+1^ ;` (с пробелом). Выравнивание TEXT `BOTTOM_*` — это низ выносных элементов, а не базовая линия.
- `compare_dxf.py`: режим `--align geom`, сопоставление текста по центру строки.
- Новый Docker-образ `docker/oda-convert` (ODA File Converter 27.9 в Xvfb) и скрипт `convert.sh`; проверен DWG‑круг.
- Приёмы наложения/метрик (`work/overlay.py`), подбор радиусов по скелету, рабочая конфигурация OCR для курсивной кириллицы ЕСКД.

## 11. Как открыть в AutoCAD (nanoCAD, КОМПАС, LibreCAD)

1. «Файл → Открыть», тип *.dxf, файл `out/klapan_variant_A.dxf` (или готовый `out/klapan_variant_A.dwg`, формат AutoCAD 2018).
2. Единицы — миллиметры, лист А3 1:1 в пространстве модели: «Показать до границ» (`ZOOM E`).
3. Шрифт стиля ESKD — `isocpeur.ttf` (входит в AutoCAD). Если система его не находит, назначьте стилю ESKD любой TTF с кириллицей (например, GOST type B) — текст хранится в UTF‑8 и не потеряется.
4. Слои MAIN (0,5 мм) / THIN / AXIS (CENTER) / DIMS / TEXT; для толщин включите «Отображать веса линий» (`LWDISPLAY`). Размеры — настоящие DIMENSION стиля ESKD: их можно редактировать, перетаскивать, менять значения.
5. Для печати: лист А3, масштаб 1:1, границы — рамка формата (0,0)–(420,297).
