# OCR в общем сервисе

Модуль использует локальный PaddleOCR PP-OCRv5 с русским распознавателем eslav. Поддерживает PDF, PNG и JPEG. Он подключён к основному API/worker; отдельный CLI нужен для диагностики. Сначала OCR читает подготовленную страницу, затем CV получает эту же страницу и маски текста. Адаптер собирает TEXT и проверенные линейные DIMENSION в DrawingGraph 0.2.

Контракт, правила исправлений и хранение: [интеграция OCR](../docs/ocr-integration.md). Проверки: [протокол](../docs/reviews/2026-11-01-ocr-fixes/verification.md).

## Окружение и модели

Для общего сервиса используйте `backend/uv.lock`, а не последовательную установку разных requirements-файлов. В окружении один поставщик `cv2`: `opencv-contrib-python`. Docker собирает это окружение автоматически.

```powershell
# Из корня репозитория, Python 3.12 и uv должны быть установлены
uv sync --project backend --locked
$env:PYTHONPATH = "$(Get-Location);$(Get-Location)\backend"
backend\.venv\Scripts\python.exe -m tools.fetch_models --download
```

Скачивание выполняется только отдельной командой подготовки. Она проверяет SHA-256 архивов и файлов. Веса находятся в `models/paddle/PP-OCRv5_mobile_det_infer` и `models/paddle/eslav_PP-OCRv5_mobile_rec_infer`. Источники и контрольные суммы — [MANIFEST.json](models/MANIFEST.json). Рабочий OCR проверяет локальные файлы и не скачивает недостающие веса.

Если путь к весам в Windows содержит кириллицу, проверенные файлы копируются в кэш с ASCII-путём: обычно `%TEMP%/practice44-ocr-models/<хеш>/`. Его можно задать переменной `DRAWING_OCR_CACHE_DIR`. Постоянное хранилище меняется через `DRAWING_OCR_MODEL_DIR`; контейнер использует `/models/paddle`.

## Диагностический запуск

```powershell
.\mlocr\run_ocr.ps1 .\mlocr\samples\Воронка.pdf
.\mlocr\run_ocr.ps1 .\mlocr\samples\Воронка.pdf -Page 1 -Dpi 300
.\mlocr\run_ocr.ps1 .\mlocr\samples\Воронка.pdf -AllPages
backend\.venv\Scripts\python.exe -m mlocr.src.cli input.png --output mlocr/results/check.json
```

PowerShell-обёртка выбирает первую страницу и PDF DPI до 300 с ограничением длинной стороны около 3800 пикселей; `-Dpi` задаёт значение явно. Python CLI без `--page` обрабатывает все страницы последовательно, максимум 20. Общий API пока поддерживает одностраничный PDF. Лимит страницы — 50 млн пикселей; допустимый PDF DPI — 72–600. PNG/JPEG нормализуются по EXIF, прозрачность накладывается на белый фон; DPI для них не применяется.

Обёртка выбирает `backend/.venv`, затем `mlocr/.venv`; иной интерпретатор задаётся через `-PythonPath`. Есть параметры `-ModelsRoot`, `-Output`, `-CvJson`. CV JSON должен относиться к точно такому же растру: проверяются хеш RGB-пикселей, размер и номер страницы. Независимый рендер PDF с другим DPI не подходит для связывания.

## Результат

- `texts`: исходное чтение `raw_text`, исправленное `text`, полигон `poly_source_px`, уверенность, альтернативы, правила исправлений и замечания.
- `notation`: тип обозначения и числа; это ещё не подтверждение связи с деталью.
- `source` и `pages`: идентификаторы растра и страницы.
- `title_block`: кандидаты названия, номера, материала и автора с ссылками на строки; при недостатке данных — `unknown`.
- `issues`: конфликты, невалидные числа и другие причины проверки человеком.

В общем сервисе исходник и результаты запуска находятся в файловом томе; PostgreSQL хранит задания, состояния, ссылки и историю. `ocr-observations.json` содержит наблюдения, `ocr.json` — результат преобразования в схему чертежа. Сведения OCR сохраняются и в `drawing.json/provenance.ocr`.

## Символы и ограничения

Маленькая латинская `m` заменяется на `т` внутри слова с кириллицей: `Сm3 → Ст3`. Латинские слова, отдельное `10m`, резьба `M12` и кириллическая `м` сохраняются. Для `8omb. → 8отв.` есть отдельное ограниченное правило сокращения.

Похожие на диаметр знаки перед числом нормализуются в `Ø`; голая буква `O` или цифра `0` автоматически диаметром не становятся. Пропущенный знак восстанавливается только по признакам перечёркнутого кольца на изображении, с замечанием `diameter_recovered` и проверкой человеком. Это эвристика, не гарантия любого шрифта. [Примеры](evaluation/notation-cases.md).

Автоматически подтверждаются линейные размеры с доказанной связью с отрезком детали и размерными/выносными линиями. Диаметры и радиусы распознаются как обозначения, но автоматический радиальный/диаметральный DIMENSION ещё не реализован. Несколько масштабов и неоднозначные привязки требуют проверки. Редактирование DXF в CAD проверяется отдельно.

## Проверки

```powershell
$env:PYTHONPATH = "$(Get-Location);$(Get-Location)\backend"
backend\.venv\Scripts\python.exe -m pytest -q backend/tests tests mlocr/tests
backend\.venv\Scripts\python.exe -m tools.evaluate_ocr --out mlocr/results/evaluation
$env:REQUIRE_LOCAL_MODELS = "true"
backend\.venv\Scripts\python.exe -m tools.ocr_acceptance --out mlocr/results/linear
```

Первая команда не требует весов Paddle. Вторая запускает настоящий OCR на трёх размеченных фрагментах и считает CER — долю ошибочных символов до/после исправлений. Это регрессионный набор, не независимая оценка качества. Третья запускает OCR и CV на контрольном чертеже и проверяет DIMENSION в DXF; нужны все модели общего сервиса.
