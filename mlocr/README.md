# Прототип OCR

Локальный прототип OCR на PaddleOCR PP-OCRv5 с русским распознаванием. Он принимает PDF, PNG и JPEG, сохраняет найденные текстовые области и чтения в JSON. Если в PDF есть текстовый слой, он извлекается и сравнивается с OCR.

## Структура

```text
mlocr/
├─ run_ocr.ps1             короткая команда запуска для Windows PowerShell
├─ requirements.txt        закреплённые зависимости Python
├─ models/
│  └─ MANIFEST.json        источники, лицензия и SHA-256 весов
├─ samples/                примеры входных PDF
├─ src/
│  ├─ cli.py               загрузка PDF/изображений, запуск PaddleOCR, запись результата
│  ├─ pdf_text.py          извлечение текста PDF, слияние с OCR, кандидаты полей штампа
│  ├─ semantics.py         разбор размерных и других инженерных обозначений
│  └─ dimension_links.py   диагностические предложения связей с точками CV
├─ tests/                  модульные проверки парсера, PDF/OCR-слияния и предложений связей
├─ evaluation/             заметки по прогонам, тестовые обозначения и пример штампа
└─ results/                JSON OCR и результаты CV; создаётся при запуске, исключена из Git
```

Веса моделей и виртуальное окружение хранятся локально и не входят в Git. `results/` содержит воспроизводимые выходные файлы, поэтому её содержимое также не коммитится.

## Первичная настройка

Из корня репозитория создайте окружение Python 3.12 и установите зависимости:

```powershell
py -3.12 -m venv mlocr/.venv
mlocr\.venv\Scripts\python.exe -m pip install --upgrade pip
mlocr\.venv\Scripts\python.exe -m pip install -r mlocr/requirements.txt
```

Скачайте архивы моделей по ссылкам из [`models/MANIFEST.json`](models/MANIFEST.json), сверьте SHA-256 и распакуйте их так, чтобы в каждом каталоге были `inference.json` и `inference.pdiparams`:

- детектор: `mlocr/models/det/PP-OCRv5_mobile_det_infer/`;
- распознаватель: `mlocr/models/eslav-rec/eslav_PP-OCRv5_mobile_rec_infer/`.

После размещения весов обработка выполняется локально. CLI получает явные пути к ним и не использует удалённые модели PaddleOCR по умолчанию.

## Входные данные и запуск

Чертёж можно положить в `mlocr/samples/` или оставить в любом другом месте и передать его путь команде. Пример из корня репозитория:

```powershell
.\mlocr\run_ocr.ps1 .\mlocr\samples\Воронка.pdf
```

По умолчанию обрабатывается первая страница. Для PDF DPI выбирается автоматически: не выше 300, с ограничением примерно до 40 мегапикселей и до 3800 пикселей по длинной стороне. Для PNG/JPEG DPI не применяется.

```powershell
# Указать страницу и DPI вручную
.\mlocr\run_ocr.ps1 .\mlocr\samples\Воронка.pdf -Page 2 -Dpi 300

# Обработать все страницы PDF
.\mlocr\run_ocr.ps1 .\mlocr\samples\Воронка.pdf -AllPages

# Указать другой путь для результата
.\mlocr\run_ocr.ps1 .\mlocr\samples\Воронка.pdf -Output .\mlocr\results\check.json
```

Можно передавать относительный или абсолютный путь к PDF/PNG/JPEG. `-Page` выбирает одну страницу PDF; `-AllPages` запускает все страницы. Если DPI не задан, используется автоматический выбор. Ручной DPI допустим от 72 до 600.

## Результат и проверка

По умолчанию JSON записывается в `mlocr/results/<имя-входа>.ocr.json`. В нём:

- `texts` — найденные строки, их ID, полигоны в пикселях страницы, угол, уверенность и альтернативные чтения;
- `source` — откуда взято основное чтение: OCR, текстовый слой PDF или оба источника;
- `notation` — результат разбора инженерного обозначения с сохранением исходной строки в `raw_text`;
- `title_block` — кандидаты полей штампа со ссылками на ID текста либо `unknown`;
- `issues` — например, расхождение OCR с текстом PDF;
- `dimension_links` — необязательные гипотезы сопоставления чисел с геометрией CV.

Для ручной проверки откройте исходный чертёж рядом с JSON, найдите текст по `polygon_px` и сравните прочитанную строку. `mlocr/evaluation/initial-results.md` содержит заметки по уже просмотренным образцам; `notation-cases.md` — примеры разбора строк.

Тесты логики запускаются из корня репозитория:

```powershell
mlocr\.venv\Scripts\python.exe -m unittest discover -s mlocr/tests -v
```

### Связь с CV-модулем

`mlcv/drawcv` может использовать полигоны OCR, чтобы маскировать текстовые области при поиске геометрии. Это проверяет взаимодействие областей текста и CV, но не точность распознанных букв. Установка и запуск CV описаны в [`mlcv/README.md`](../mlcv/README.md). Для добавления диагностических гипотез размерных связей в OCR JSON можно передать готовый `cv.json` параметром `-CvJson`.

## Разбор обозначений

Исходная строка не переписывается. `Ø` (U+00D8) и `⌀` (U+2300) разбираются как знаки диаметра. `φ`, `∅` и кириллическая `Ф/ф` остаются неоднозначными кандидатами `diameter_candidate`. Сам знак не подтверждает связь с геометрией.
