# Результаты первичного локального запуска OCR

Модель: PaddleOCR 3.7.0 / PaddlePaddle 3.2.0, детектор PP-OCRv5 mobile и распознаватель `eslav_PP-OCRv5_mobile_rec`, CPU. Веса и SHA-256 архивов указаны в [`../models/MANIFEST.json`](../models/MANIFEST.json). Входные PDF находятся в [`../samples/`](../samples/). JSON-результаты лежат в игнорируемой Git папке `mlocr/results/`.

## Наблюдения

| Фрагмент | Ожидаемые примеры | Результат первого прохода | Примечания |
|---|---|---|---|
| Размеры | `46`, `20`, `14`, `R3`, `Ø42`, `Ø32`, `Ø28`, `M12×1,5-H7`, `Ø135`, `Ø150±0,5` | После добавления прохода с поворотом на 90° верно прочитаны `46`, `20`, `14`, `R3` и `M12×1,5-H7`. Диаметры распознаны как `042`, `32`, `028`, `135` и `0150±0,5` | Поворот помогает прочитать вертикальные строки, но знак диаметра теряется или распознаётся как ноль. Сохраняем исходное чтение; семантику диаметра автоматически не подтверждаем. |
| Примечания | Русский текст, `H14`, `h14`, `±IT15/2`, `3…5 мм`, стандарты | Большинство фраз прочитано правильно, в том числе `Требования предъявляемые`, `Неуказанные предельные отклонения`, `Маркировать`; в `3...5мм`, `±IT15/2` и похожих латинских/кириллических символах есть ошибки | Крупный горизонтальный текст читается хорошо; инженерные символы и смешанные алфавиты нужно тщательно проверять. |
| Штамп | `Клапан предохранительный`, `АЛ-9`, `ГОСТ 2685-75`, `0,385` | Распознаны `Клапан`, `предохранительный`, `0,385`; `АЛ-9` прочитано как `Ал-9`, в `ГОСТ` перепутаны похожие латинские буквы, одна подпись строки штампа прочитана неверно | Значения извлекаются, но в этом прогоне их назначение полям штампа ещё не определялось. |

Запуск использовал явные пути к локальным моделям. PaddleOCR загрузил модели из этих папок и завершил работу без шага скачивания. Использовался CPU; на этой машине каждый новый процесс занимал примерно 25–35 секунд вместе с инициализацией моделей. Два прохода сохраняют оба чтения и выводят основным вариант с большей уверенностью. Эти наблюдения получены только на трёх фрагментах одного чертежа.

В JSON результата теперь есть координаты на исходной странице, устойчивые ID текста, ориентация, альтернативные чтения, осторожный разбор обозначения и подсказка о назначении. В [`title-block-example.json`](title-block-example.json) приведён проверенный вручную пример разбора штампа: название остаётся кандидатом со ссылками на ID OCR; номер документа, материал и авторы остаются неизвестными, если ячейка пустая или неоднозначная.

## Дополнительный пример: PDF с чертежом гайки

Вход: страница 1 PDF из `mlocr/samples`, растеризованная с разрешением 300 DPI. JSON OCR и изображение страницы находятся в игнорируемой папке результатов.

| Ожидалось по изображению | Выход OCR | Оценка |
|---|---|---|
| `30`, `6.5`, `28`, `35`, `65` | Точные строки | Прочитано верно; связь с геометрией не оценивалась. |
| Диаметр `72` | Греческая `φ` перед `72` | Парсер оставляет неоднозначного кандидата диаметра и добавляет предупреждение. |
| Диаметр `64` | `64` | Знак диаметра потерян; парсер видит обычное линейное значение. Автокоррекция не выполняется. |
| `M56x2-7H` | Точная строка | Парсер выделяет номинал 56, шаг 2 и класс 7H. |
| Номер чертежа, название детали, материал, масса, масштаб | Большинство значений прочитано; название детали разделено на области | Назначение полей штампа ещё не проверялось. |

На этом чистом листе OCR полезен для размеров, кириллических подписей и обозначения резьбы, но видны потери символов, ошибки разделения областей и отсутствие подтверждённых связей размеров с геометрией. Сейчас проходят 11 модульных тестов: 7 тестов парсера обозначений и 4 теста слияния PDF/OCR и предложений связей.

## Текстовый слой PDF и прототип связей размеров

Для `Воронка.pdf` выбираемый текст PDF объединяется с наблюдениями OCR по пересекающимся областям на исходной странице. Где доступен текстовый слой PDF, он используется как основное чтение; результат OCR и расхождения сохраняются отдельно. В этом файле знак перед `14` закодирован в текстовом слое как `∅` (U+2205), а распознавание растра даёт `φ` (греческая фи). JSON сохраняет оба чтения и помечает расхождение. Ни один из этих символов сам по себе не подтверждает диаметр.

Обработчик штампа предлагает `Воронка` как название и `17.XXXX.02` как номер документа; оба значения связаны с ID исходного текста. Материал и авторы имеют статус `unknown`: алгоритм не заполняет их догадками по соседним надписям. Это первая эвристика для данного оформления, а не поддержка всех видов штампов.

Маскирование текста CV запускалось с объединённым OCR JSON: получено 36 текстовых областей, статус CV — `ok`. Необязательный параметр `--cv-json` предлагает пары точек CV, расстояние между которыми совпадает с линейным номиналом OCR. На этом листе для `66` найдено 66 геометрически возможных пар, для `32` — 73, для `28` — 5, для `10` — 2. Все остаются `needs_review`: совпадение длины и близость надписи помогают упорядочить гипотезы, но не доказывают принадлежность выносных линий. CV также запускался на `бобышка.pdf` и `втулка.pdf`; там найдены пропуски или несколько гипотез, без независимо проверенной автоматической связи. Диагностическая интеграция пункта 4 работает, но критерий с одной подтверждённой автоматической связью пока не достигнут.

Локальный запуск требует явных каталогов с весами моделей и использует локальные пути на CPU. Благодаря этому конфигурация не переключается на удалённые модели PaddleOCR по умолчанию. Проверка с полностью отключённой сетью пока не зафиксирована.
